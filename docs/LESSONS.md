# 실수 기록 (LESSONS)

이 저장소에서 실제로 생긴 문제를 모두 적는다. 새 문제가 생기면 같은 형식으로 **맨 아래에 추가**하고, 재발 방지 테스트나 규칙을 반드시 함께 남긴다. 요약 규칙은 [CLAUDE.md](../CLAUDE.md)에 있다.

형식: 증상 → 원인 → 해결 → 재발 방지

---

## A. 제품 코드 버그

### A1. 되돌리기 기록 없이 파일이 옮겨질 수 있었음 (심각)
- 증상: 대상 폴더에 로그를 쓸 수 없으면 `flush()`가 오류를 삼키고 이동은 계속됨 → 되돌리기 불가
- 원인: "로그 저장 실패는 무시" 처리
- 해결: `RunLog`가 첫 파일을 옮기기 **전에** 로그를 저장하고, 실패하면 예외 → 아무것도 옮기지 않음. CLI·GUI는 `err_log_write` 표시
- 재발 방지: `test_log_cannot_be_written_moves_nothing`, `test_run_with_unwritable_log_shows_error`. 규칙: **되돌리기 수단이 확보되기 전에는 파일을 건드리지 않는다**

### A2. 재실행할 때마다 `곡 (2).mp3`가 `곡 (3).mp3`로 바뀜
- 원인: 충돌 검사에서 파일 자신의 현재 경로를 "이미 있는 파일"로 셈
- 해결: `os.path.lexists(dst) and normcase(dst) != normcase(src)`; 자기 자리면 "변경 없음"
- 재발 방지: `test_numbered_files_stay_numbered_on_the_next_run`. 규칙: **충돌 번호가 생기는 경우의 재실행(멱등성) 테스트를 항상 둔다**

### A3. 같은 태그 5,000개 미리보기 46초 (O(n²))
- 원인: 파일마다 `(2)`부터 다시 세며 `lexists` 호출
- 해결: 이름별 마지막 번호를 기억(`counters`) → 2.8초
- 재발 방지: `test_five_thousand_files_preview_is_fast`. 규칙: **최악 입력(전부 같은 태그)으로 성능을 잰다**

### A4. NFC/NFD로만 다른 두 파일을 한 파일로 취급
- 증상: GUI 표 iid 충돌 가능, 덮어쓰기 판정 혼동
- 원인: 식별 키(`key_of`)에 NFC 정규화를 넣음. NTFS는 두 이름을 다른 파일로 둔다
- 해결: 식별은 `key_of`(대소문자만 무시), 새 이름 충돌 판정은 `target_key`(NFC 포함)로 분리
- 재발 방지: `test_nfc_and_nfd_twins_stay_two_files`, `test_nfc_nfd_twins_do_not_break_the_table`

### A5. 읽기 전용 파일 처리 실패
- 증상: 다른 드라이브 이동 시 원본 삭제 실패, 복사 모드 되돌리기 시 사본 삭제 실패. 실제 폴더의 flac 30개가 읽기 전용이었음
- 해결: `mover.remove_file()` — 읽기 전용일 때만 속성을 풀고 지우며, 실패하면 속성 복구
- 재발 방지: `test_read_only_*`, `test_cross_drive_read_only_move_and_undo`. 규칙: **실제 데이터에는 읽기 전용·숨김 파일이 있다고 가정한다**

### A6. 되돌리기 중 취소 후 다시 되돌리면 "파일 없음"이 쏟아짐
- 해결: 취소 시 아직 처리하지 않은 작업만 로그에 남김
- 재발 방지: `test_cancelled_undo_continues_next_time`

### A7. 빈 치환자만 있는 폴더 자리에 `_` 폴더 생성 (`{artist}/{disc}/{title}`)
- 해결: 대체 문구 없는 치환자가 비어 폴더 이름이 없어지면 그 단계를 건너뜀
- 재발 방지: `test_empty_folder_placeholder_is_dropped`

### A8. 태그 속 줄바꿈·탭이 지워져 단어가 붙음 (`Line\nbreak` → `Linebreak`)
- 해결: 제어문자를 공백으로 바꾼 뒤 연속 공백 정리
- 재발 방지: `test_odd_tag_text_survives`

### A9. 깨진 `organize_log.json`을 새 실행이 덮어씀 (되돌리기 기록 유실)
- 해결: 읽을 수 없는 로그는 `.broken-날짜`로 옮겨 보관
- 재발 방지: `test_broken_log_is_kept_aside`

### A10. 미리보기 뒤 원본이 사라지면 빈 대상 폴더가 남음
- 해결: 폴더를 만들기 전에 원본 존재 확인
- 재발 방지: `test_source_vanishes_between_preview_and_run`

### A11. GUI 표(Treeview)가 텅 비어 보임
- 원인: 스크롤 상자 프레임을 표보다 **나중에** 만들어 쌓임 순서상 표를 가림
- 해결: `tree.lift(box)`
- 재발 방지: 규칙 — **GUI를 바꾸면 반드시 스크린샷을 찍어 눈으로 확인한다** (테스트가 통과해도 화면은 비어 있었음)

### A12. 가수 통합 탭의 파일 수가 부풀려짐 (157 → 179)
- 원인: 가수·앨범 가수 두 필드를 따로 셈
- 해결: 고유 파일 수로 계산
- 규칙: 숫자를 화면에 낼 때는 실제 데이터로 손으로 검산

### A13. 정리 규칙 입력칸이 좁아 규칙이 잘림
- 원인: 긴 치환자 안내문을 같은 줄에 둠
- 해결: 안내문을 다음 줄로

### A14. 작업 스레드에서 tk 변수를 읽음
- 원인: `self.options()`(tk `StringVar.get`)를 worker 안에서 호출
- 해결: 스레드 시작 전에 값을 읽어 넘김. 규칙: **worker 함수 안에서는 위젯·tk 변수에 손대지 않는다**

### A15. 디자인 개편 때 스크린샷으로 잡은 문제들
- 제목이 명조체처럼 보임: `Segoe UI`에는 한글이 없어 Windows가 바탕체로 대체 → 언어별 UI 폰트(ko 맑은 고딕, ja Yu Gothic UI, zh YaHei UI)
- 일본어·중국어 화면에서 표의 한글 파일명이 흐릿함: Yu Gothic·YaHei에 한글이 없음 → 파일명 표는 언어와 상관없이 맑은 고딕(한·중·일 모두 있음)
- 경로 구분자가 언어마다 `₩`·`¥`로 보임(한·일 폰트의 백슬래시) → 표의 상대 경로는 `/`로 표시
- 보조 버튼이 글자처럼 보임: clam 테마에서 `relief="flat"`이 테두리를 지움 → `relief="raised"` + 테두리 색
- 실행 버튼 줄이 창 밖으로 밀림: 본문을 먼저 `expand`로 pack → 하단 바를 `side="bottom"`으로 먼저 pack
- 최소 크기에서 표 높이 0, 안내문·요약 잘림, 버튼 잘림 → 최소 높이 800(화면보다 크지 않게), 안내문은 `<Configure>`로 줄바꿈 폭 조정, 버튼을 상태 영역보다 먼저 pack
- 재발 방지: 규칙 — **GUI를 바꾸면 기본 크기와 최소 크기 둘 다, 4개 언어로 스크린샷**

## B. 실제 데이터에서 알게 된 것 (기본값을 바꾼 이유)

- B1. 56곡이 트랙 태그 없이 `01.제목.mp3` → 파일명 앞 숫자를 트랙으로 사용
- B2. "같은 곡" 중복이 베스트 앨범 곡과 원래 앨범 곡을 묶음 → GUI는 2·3단계 자동 적용 안 함. CLI `--dedupe`는 전부 적용(실제 폴더에서 77개 이동)하므로 사용 전 `--dry-run` 권장
- B3. `.cue`·`.log`·`Artwork`가 있는 앨범 폴더는 비지 않아 남음 (PRD 범위 밖, 사용자에게 알림)
- B4. 사용자가 직접 빌드된 exe로 원본 폴더를 정리한 상태(`music\tmp`)가 테스트 중 발견됨 → 원본은 매 작업 전후 상태를 확인하고, 사용자 파일은 대신 되돌리지 않고 알린다

## C. 테스트 코드 실수

- C1. 설정 파일(`settings.json`)을 스냅샷 대상 폴더 안에 둬서 비교가 깨짐 → 설정은 `tmp_path_factory`의 별도 폴더
- C2. `Thumbs.db` 같은 정크 파일은 빈 폴더와 함께 지워지므로 "복원 후 동일" 비교에서 빼야 함
- C3. 테스트 폴더 이름 `a/b`가 대상 `A/B`와 대소문자만 달라 Windows에서 같은 폴더 → 테스트용 이름이 대상 경로와 겹치지 않게
- C4. "어느 파일을 남기나 / 대표 이름이 뭔가"를 짐작으로 적음 → 규칙(무손실 > 비트레이트 > 제자리 > 짧은 경로, 파일 수 많은 표기)을 계산해서 기대값을 쓴다
- C5. `importlib`으로 다른 저장소 모듈을 불러올 때 `sys.modules`에 등록하지 않아 dataclass 오류
- C6. 테스트마다 `Tk()`를 새로 만들면 "Can't find a usable tk.tcl"로 간헐 실패 → 모듈 단위로 Tk 하나 공유
- C7. 한 테스트가 통과했다고 끝내지 않는다: GUI 테스트는 3번 연속 돌려 간헐 실패를 확인

## D. 작업 방식 실수 (도구·환경)

- D1. Git Bash의 `/c/Users/...` 경로를 Python 문자열에 그대로 넣어 아무 일도 안 일어남(오류도 없음) → Python에는 `C:\...` Windows 경로
- D2. heredoc 안 Python 치환 스크립트의 백슬래시 이스케이프가 어긋나 수정 실패 → 정규식·백슬래시가 든 수정은 Edit 도구로
  - **재발 2 (메모 갱신 중)**: 기록 직후에도 `C:\...`, `music\tmp`가 든 문장을 heredoc Python으로 고치다 또 실패. 습관으로는 안 막힌다 → 규칙: **고칠 문장에 `\`가 하나라도 있으면 Bash를 쓰지 않고 바로 Edit 도구**. 메모리 파일도 마찬가지
  - **재발 (커밋 준비 중)**: Windows 경로(`C:\Users\...`)가 든 줄을 heredoc Python으로 고치다 `\U` 이스케이프 오류. 실패한 줄 다음 명령(git add)이 그대로 실행돼 고치기 전 파일이 스테이징됨. → 경로가 든 수정은 **예외 없이** Edit 도구로, 수정과 다른 명령을 `&&` 없이 한 덩어리로 묶지 않는다
- D11. 공개 저장소에 올라갈 파일에 개인 경로(사용자 이름이 든 `C:\Users\...`)가 들어감 → 커밋 전 `grep`으로 개인 경로를 찾고, 로컬 전용 정보는 `CLAUDE.local.md`(.gitignore)에
- D3. 코드 수정 중 기존 변수명(`base`)을 다른 뜻으로 재사용해 버그 → 수정 후 함수 전체를 다시 읽는다
- D4. `cmd //c build.bat`가 Git Bash에서 실패 → PowerShell에서 절대 경로로 실행
- D5. 사용자가 앱을 켜 둔 상태라 exe 덮어쓰기 실패 → 빌드 전에 실행 중인 프로세스를 확인하고, 사용자의 앱은 끄지 않는다. 다른 폴더(`build\dist-new`)에 빌드
- D6. `dist\settings.json`에는 사용자의 `last_log`(되돌리기 경로)가 있음 → 빌드·정리 때 지우지 말고 백업
- D7. 저장소에서 `python main.py`를 돌리면 `settings.json`이 저장소에 생기고 `last_log`가 테스트 경로로 바뀜 → 끝나면 삭제(.gitignore에 있음)
- D8. Windows 콘솔 cp949 때문에 일본어·중국어 출력이 깨지거나 예외 → `PYTHONIOENCODING=utf-8`
- D9. 스크린샷이 잠금 화면을 찍음 → 찍은 이미지를 반드시 열어 확인
- D10. 실제 폴더 복사본 정리 시 읽기 전용 파일 때문에 `rmtree` 실패 → `onexc`에서 `chmod` 후 삭제
