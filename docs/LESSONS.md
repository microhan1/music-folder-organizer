# 실수 기록 (LESSONS)

이 저장소에서 실제로 생긴 문제를 모두 적는다. 새 문제가 생기면 같은 형식으로 **맨 아래에 추가**하고, 재발 방지 테스트나 규칙을 반드시 함께 남긴다. 요약 규칙은 [CLAUDE.md](../CLAUDE.md)에 있다.

형식: 증상 → 원인 → 해결 → 재발 방지

## A. 제품 코드 버그

### A1. 되돌리기 기록 없이 파일이 옮겨질 수 있었음 (심각)
- 증상: 대상 폴더에 로그를 쓸 수 없으면 `flush()`가 오류를 삼키고 이동은 계속됨 → 되돌리기 불가
- 원인: "로그 저장 실패는 무시" 처리
- 해결: `RunLog`가 첫 파일을 옮기기 **전에** 로그를 저장하고, 실패하면 예외 → 아무것도 옮기지 않음. CLI·GUI는 `err_log_write` 표시
- 재발 방지: `test_log_cannot_be_written_moves_nothing`, `test_run_with_unwritable_log_shows_error`. 규칙: **되돌리기 수단이 확보되기 전에는 파일을 건드리지 않는다**

### A2. 재실행할 때마다 `곡 (2).mp3`가 `곡 (3).mp3`로 바뀜
- 원인: 충돌 검사에서 파일 자신의 현재 경로를 "이미 있는 파일"로 셈
- 해결: `os.path.lexists(dst) and normcase(dst) != normcase(src)`; 자기 자리면 "변경 없음"
- 재발 방지: `test_numbered_files_stay_numbered_on_the_next_run`. 규칙: **충돌 번호가 생기는 경우의 재실행(멱등성) 테스트를 항상 둔다**

### A3. 같은 태그 5,000개 미리보기 46초 (O(n²))
- 원인: 파일마다 `(2)`부터 다시 세며 `lexists` 호출
- 해결: 이름별 마지막 번호를 기억(`counters`) → 2.8초
- 재발 방지: `test_five_thousand_files_preview_is_fast`. 규칙: **최악 입력(전부 같은 태그)으로 성능을 잰다**

### A4. NFC/NFD로만 다른 두 파일을 한 파일로 취급
- 증상: GUI 표 iid 충돌 가능, 덮어쓰기 판정 혼동
- 원인: 식별 키(`key_of`)에 NFC 정규화를 넣음. NTFS는 두 이름을 다른 파일로 둔다
- 해결: 식별은 `key_of`(대소문자만 무시), 새 이름 충돌 판정은 `target_key`(NFC 포함)로 분리
- 재발 방지: `test_nfc_and_nfd_twins_stay_two_files`, `test_nfc_nfd_twins_do_not_break_the_table`

### A5. 읽기 전용 파일 처리 실패
- 증상: 다른 드라이브 이동 시 원본 삭제 실패, 복사 모드 되돌리기 시 사본 삭제 실패. 실제 폴더의 flac 30개가 읽기 전용이었음

- 재발 방지: `test_read_only_*`, `test_cross_drive_read_only_move_and_undo`. 규칙: **실제 데이터에는 읽기 전용·숨김 파일이 있다고 가정한다**

### A6. 되돌리기 중 취소 후 다시 되돌리면 "파일 없음"이 쏟아짐

### A15. 디자인 개편 때 스크린샷으로 잡은 문제들
- 제목이 명조체처럼 보임: `Segoe UI`에는 한글이 없어 Windows가 바탕체로 대체 → 언어별 UI 폰트(ko 맑은 고딕, ja Yu Gothic UI, zh YaHei UI)
- 일본어·중국어 화면에서 표의 한글 파일명이 흐릿함: Yu Gothic·YaHei에 한글이 없음 → 파일명 표는 언어와 상관없이 맑은 고딕(한·중·일 모두 있음)
- 경로 구분자가 언어마다 `₩`·`¥`로 보임(한·일 폰트의 백슬래시) → 표의 상대 경로는 `/`로 표시

- 최소 크기에서 표 높이 0, 안내문·요약 잘림, 버튼 잘림 → 최소 높이 800(화면보다 크지 않게), 안내문은 `<Configure>`로 줄바꿈 폭 조정, 버튼을 상태 영역보다 먼저 pack
- 재발 방지: 규칙 — **GUI를 바꾸면 기본 크기와 최소 크기 둘 다, 4개 언어로 스크린샷**

### A16. 짝 도구가 적는 iTunes 아티스트 ID를 읽지 않음
- 증상: music-tag-filler는 iTunes 후보로 채운 곡에 `TXXX:iTunes Artist Id` / `ITUNES_ARTISTID` / `----:com.apple.iTunes:iTunes Artist Id`를 적는데, 이 도구는 m4a의 `atID`만 읽어 그 곡들은 ID로 묶이지 않음. README 상호 링크를 쓰다 두 코드를 대조해서 발견
- 원인: 짝 도구의 실제 출력 형식을 확인하지 않고 "있을 법한" 칸만 읽음
- 해결: 세 형식 모두 읽고(`itunes_artist_id`), MusicBrainz·iTunes 중 어느 ID든 같으면 같은 가수로 묶음(두 ID 공간은 `mb:`·`itunes:`로 분리)
- 재발 방지: `test_ids_written_by_music_tag_filler_merge_artists` — **짝 도구의 실제 쓰기 함수로 쓴 파일을 읽는 통합 테스트**. 규칙: 다른 도구와의 연동을 문서에 적기 전에 그 도구의 코드와 테스트로 형식을 확인한다

### A17. 중복을 정리하고 다시 실행하면 가수 폴더 이름이 뒤집힘
- 증상: `岡田有希子`(파일 3개)·`岡田 有希子`(1개) → 첫 실행은 `岡田有希子` 폴더. 중복 2개가 `_중복`으로 빠지자 1:1이 되어 두 번째 실행에서 대표 이름이 `岡田 有希子`로 바뀌고 정리된 파일을 또 옮김. v0.2.0 2번(같은 앨범 중복 기본 적용) GUI 테스트에서 드러남
- 원인: 대표 이름을 그때그때의 "파일 수가 많은 표기"로만 정함. 파일 수는 실행 결과에 따라 변함
- 해결: 고른 문자 체계 안에서 **이미 그 이름의 폴더가 있는 표기를 먼저** (`existing_folders` → `ArtistIndex(existing=...)`)
- 재발 방지: `test_rerun_after_duplicates_left_moves_nothing`, `test_existing_folder_keeps_the_artist_name`. 규칙: **실행 결과로 바뀌는 값(파일 수 등)으로 이름을 정하면 재실행이 흔들린다 — 이미 디스크에 있는 것을 먼저 존중**

### A18. 긴 원본 경로가 "폴더 선택…" 버튼을 밀어냄 (A15 재발)
- 증상: 실제 폴더 사본(긴 경로)을 열자 버튼이 "폴더 ㅅ"로 잘림. 데모 폴더(짧은 경로) 스크린샷에서는 안 보였음
- 원인: A15와 같은 pack 순서 — 늘어나는 라벨을 버튼보다 먼저 pack
- 해결: 버튼 먼저 `side="right"`로 pack
- 재발 방지: 규칙 — **스크린샷은 짧은 데모 경로와 긴 실제 경로 둘 다로**. 한 줄에 "늘어나는 것 + 고정 크기 것"이 있으면 고정 크기를 먼저 pack
- **재발 3 (v0.3.0 설정 버튼)**: 머리글의 제목·소개 묶음을 먼저 pack하고 "설정" 버튼을 오른쪽에 나중에 추가 → 영어 최소 폭에서 버튼이 납작해짐. 규칙을 적어 두고도 **기존 줄에 위젯을 덧붙일 때** 순서를 다시 보지 않음. 해결: 오른쪽 고정 위젯을 먼저 pack. 규칙 보강: **한 줄에 위젯을 추가할 때마다 그 줄 전체의 pack 순서를 다시 읽고, 최소 폭 영어(가장 긴 문구) 스크린샷으로 확인**
- **재발 (같은 날, 음악 정보 채우기 버튼)**: 나중에 필요할 때만 나타나는 버튼을 `pack()` 하면 이미 pack된 라벨 뒤에 줄을 선다 → 기본 폭에서 "음악"으로 잘림. 최소 폭 스크린샷에선 라벨이 줄바꿈되어 안 보였음. 해결: `pack(..., before=라벨)`. 규칙: **나중에 보였다 숨겼다 하는 위젯은 `before=`로 자리를 지정**하고, 기본 폭 스크린샷도 반드시 본다

### A21. 실행 중간에 로그 저장이 실패해도 계속 옮김 (A1을 반만 고침, 심각)
- 증상: 첫 저장 뒤 로그 파일이 잠기거나(다른 프로그램·읽기 전용) 디스크가 차면, 50개마다 하는 중간 저장 `RunLog.flush()`가 오류를 삼키고 60개를 모두 옮김. 결과에는 실패가 하나도 없고, 되돌리기에는 기록되지 않은 파일이 빠짐. 사용자 코드 리뷰로 발견
- 원인: A1 때 `__init__`의 첫 저장만 예외를 던지게 바꾸고 `flush()`의 `except OSError: pass`는 그대로 둠. 고쳤다 해도 로그 저장 실패를 그대로 `OSError`로 던지면 `execute()`의 파일별 `except OSError`에 잡혀 "그 파일만 실패"로 처리되어 계속 진행했을 것
- 해결: `LogWriteError(OSError)`를 만들어 `flush()`가 던지게 함. `execute()`의 세 반복문(곡·부속 파일·빈 폴더)이 이를 `except OSError`보다 먼저 받아 `cancelled`로 멈춤. 이미 옮긴 파일은 `done`에 셈(기록은 메모리에 있음). `finally`에서 한 번 더 저장하고, 성공하면 `err_log_stopped`, 실패하면 `err_log_lost`를 `res.failed`에 넣어 화면에 보임
- 같은 패턴이 `undo.py` 끝에도 있었음: 파일은 되돌리고 "되돌림" 저장 실패는 삼킴 → 기록에는 안 되돌린 실행으로 남음. 되돌리기 전에 로그를 한 번 저장해 써지는지 확인하고(안 되면 `log_error`, 아무것도 안 옮김), 끝 저장 실패는 `log_unsaved`로 GUI·CLI에 표시
- 고치며 하나 더 발견: `save_log`가 실패하면 `organize_log.json.part`가 남았음 → 실패 시 지우게 함(되돌리기 시험의 스냅샷 비교가 잡음)
- 재발 방지: `test_log_becomes_unwritable_mid_run_stops`(읽기 전용으로 바꾼 뒤 60개 → 48개에서 멈춤, `.part` 없음), `test_log_save_fails_once_then_undo_restores_everything`(한 번만 실패 → 되돌리기로 스냅샷 동일), `test_undo_with_unwritable_log_puts_nothing_back`, `test_undo_log_save_fails_at_the_end_is_reported`, `test_cli_undo_reports_log_errors`, `test_undo_with_unwritable_log_shows_error`(GUI). 옛 코드에서 실패하는 것 확인. 규칙: **원칙("기록 없이 옮기지 않는다")을 고칠 때는 그 함수 하나가 아니라 같은 기록을 쓰는 모든 경로를 `grep`으로 찾아 함께 고친다. 특정 원인으로 멈춰야 하는 오류는 넓은 `except`에 묻히지 않게 전용 예외로 만든다**

## C. 테스트 코드 실수

- C1. 설정 파일(`settings.json`)을 스냅샷 대상 폴더 안에 둬서 비교가 깨짐 → 설정은 `tmp_path_factory`의 별도 폴더
- C2. `Thumbs.db` 같은 정크 파일은 빈 폴더와 함께 지워지므로 "복원 후 동일" 비교에서 빼야 함
- C3. 테스트 폴더 이름 `a/b`가 대상 `A/B`와 대소문자만 달라 Windows에서 같은 폴더 → 테스트용 이름이 대상 경로와 겹치지 않게
  - **재발 (v0.3.0 되돌리기 기록 테스트)**: 원본 `a/`·`c/`와 대상 `A/`·`C/`가 또 겹쳐 mkdir 수·빈 폴더 결과가 어긋남 → 원본 폴더는 `in1/`·`in2/`처럼 **가수·앨범 이름으로 쓰지 않는 이름**으로 짓는다(규칙으로 고정)
- C4. "어느 파일을 남기나 / 대표 이름이 뭔가"를 짐작으로 적음 → 규칙(무손실 > 비트레이트 > 제자리 > 짧은 경로, 파일 수 많은 표기)을 계산해서 기대값을 쓴다
- C5. `importlib`으로 다른 저장소 모듈을 불러올 때 `sys.modules`에 등록하지 않아 dataclass 오류
- C6. 테스트마다 `Tk()`를 새로 만들면 "Can't find a usable tk.tcl"로 간헐 실패 → 모듈 단위로 Tk 하나 공유
- C7. 한 테스트가 통과했다고 끝내지 않는다: GUI 테스트는 3번 연속 돌려 간헐 실패를 확인

## D. 작업 방식 실수 (도구·환경)

- D1. Git Bash의 `/c/Users/...` 경로를 Python 문자열에 그대로 넣어 아무 일도 안 일어남(오류도 없음) → Python에는 `C:\...` Windows 경로
- D2. heredoc 안 Python 치환 스크립트의 백슬래시 이스케이프가 어긋나 수정 실패 → 정규식·백슬래시가 든 수정은 Edit 도구로
  - **재발 3 (v0.2.0 화면 확인 중)**: 스크린샷을 합치는 한 줄짜리 `python -c`에 Windows 경로(`{S}\ui_...`)를 넣어 `\u` 이스케이프 오류. 수정이 아니라 **명령 안의 Python 코드**에서도 같은 함정 → 경로를 다루는 Python은 Write 도구로 파일에 쓰고 `os.path.join`으로 경로를 만든다
  - **재발 2 (메모 갱신 중)**: 기록 직후에도 `C:\...`, `music\tmp`가 든 문장을 heredoc Python으로 고치다 또 실패. 습관으로는 안 막힌다 → 규칙: **고칠 문장에 `\`가 하나라도 있으면 Bash를 쓰지 않고 바로 Edit 도구**. 메모리 파일도 마찬가지
  - **재발 (커밋 준비 중)**: Windows 경로(`C:\Users\...`)가 든 줄을 heredoc Python으로 고치다 `\U` 이스케이프 오류. 실패한 줄 다음 명령(git add)이 그대로 실행돼 고치기 전 파일이 스테이징됨. → 경로가 든 수정은 **예외 없이** Edit 도구로, 수정과 다른 명령을 `&&` 없이 한 덩어리로 묶지 않는다
- D11. 공개 저장소에 올라갈 파일에 개인 경로(사용자 이름이 든 `C:\Users\...`)가 들어감 → 커밋 전 `grep`으로 개인 경로를 찾고, 로컬 전용 정보는 `CLAUDE.local.md`(.gitignore)에
- D3. 코드 수정 중 기존 변수명(`base`)을 다른 뜻으로 재사용해 버그 → 수정 후 함수 전체를 다시 읽는다
- D4. `cmd //c build.bat`가 Git Bash에서 실패 → PowerShell에서 절대 경로로 실행
- D5. 사용자가 앱을 켜 둔 상태라 exe 덮어쓰기 실패 → 빌드 전에 실행 중인 프로세스를 확인하고, 사용자의 앱은 끄지 않는다. 다른 폴더(`build\dist-new`)에 빌드
- D6. `dist\settings.json`에는 사용자의 `last_log`(되돌리기 경로)가 있음 → 빌드·정리 때 지우지 말고 백업
- D7. 저장소에서 `python main.py`를 돌리면 `settings.json`이 저장소에 생기고 `last_log`가 테스트 경로로 바뀜 → 끝나면 삭제(.gitignore에 있음)
- D8. Windows 콘솔 cp949 때문에 일본어·중국어 출력이 깨지거나 예외 → `PYTHONIOENCODING=utf-8`
- D9. 스크린샷이 잠금 화면을 찍음 → 찍은 이미지를 반드시 열어 확인
- D10. 실제 폴더 복사본 정리 시 읽기 전용 파일 때문에 `rmtree` 실패 → `onexc`에서 `chmod` 후 삭제
- D12. 디버그 명령 앞에 남은 `cat > 파일`이 표준 입력을 기다려 2분 동안 멈춤(heredoc은 뒤의 python에 붙음) → 스크립트는 Write 도구로 파일에 쓰고 실행한다
- D13. GUI 시험이 화면 잠금·절전 중 몇 시간씩 멈춘 채 통과함(창 이벤트가 안 돎) → GUI 시험은 `timeout`을 걸고 돌리고, 시간이 비정상이면 다시 돌려 확인한다
