## 음악 폴더 정리 v0.4.0

곡이 많은 라이브러리(1만 곡 이상)에서도 빠르고 멈추지 않게 다듬은 버전입니다.

### 바뀐 것

- **바뀌지 않은 파일은 다시 읽지 않습니다.** 실행·되돌리기·음악 정보 채우기에서 돌아올 때 모든 곡의 태그를 다시 읽던 것을, 바뀐 파일만 읽게 했습니다. 같은 드라이브 안에서 옮긴 파일도 알아봅니다. 중복 찾기의 해시와 소리 비교 지문도 같은 방식으로 다시 쓰므로, 소리 비교를 다시 눌러도 바뀐 파일만 계산합니다.
- **정리 규칙이나 옵션을 바꿔도 창이 멈추지 않습니다.** 새 경로 계산을 뒤에서 하고, 그동안 아래에 "새 경로 계산 중…"이 보입니다. 계산이 끝나기 전에는 "실행"이 꺼져 있어, 바꾸기 전 계획으로 실행되는 일이 없습니다(전에는 바꾼 직후 아주 짧은 순간에 누르면 그럴 수 있었습니다).
- **중복 찾기 탭은 정리할 것이 있는 그룹만 보여 줍니다.** 원래 앨범과 베스트 앨범처럼 여러 앨범에 실려 모두 남기는 그룹은 숨기고, **모두 보기**로 전부 볼 수 있습니다(실제 라이브러리 예: 61개 → 9개).
- **되돌리기 기록을 더 가볍고 안전하게 씁니다.** 실행 중에는 기록 파일 옆 `.journal` 파일에 한 줄씩 덧붙이고, 끝나면 한 번에 합칩니다. 실행 도중 프로그램이 꺼져도 거의 모든 기록이 남아 되돌릴 수 있습니다(전에는 최근 최대 49개가 빠질 수 있었음). 기록 형식은 그대로라 이전 버전으로 정리한 것도 되돌릴 수 있습니다.

1만 곡(같은 PC, 이전 버전 → 이번): 같은 폴더 다시 열기 13.8초 → 3.4초, 실행 후 다시 읽기까지 27.7초 → 9.8초, 되돌리기 후 다시 읽기까지 22.5초 → 11.5초. 규칙을 바꾸는 동안 창이 멈추던 1.5초는 0.07초로 줄었습니다. 처음 폴더를 여는 시간은 거의 같습니다(태그를 처음 읽는 시간).

### 고친 것

- 경로가 260자를 넘는 깊은 폴더의 곡을 읽지도 옮기지도 못하던 문제(Windows 긴 경로 설정이 꺼진 PC). cue 시트, 중복 확인, 되돌리기 기록 찾기, 소리 비교까지 모두 긴 경로를 다룹니다.
- 맥에서 복사한 폴더의 `._곡.mp3` 같은 숨은 파일이 곡으로 읽혀 옮겨지던 문제. 이제 정크 파일로 보고 빈 폴더 판정에서도 무시합니다.
- 화면 배율이 높은(150 % 등) 모니터에서 창이 작게 열려 옵션 줄과 표가 좁던 문제.
- 되돌리기 기록 저장이 실행 중간에 실패해도 계속 옮기던 문제(v0.3.1에서 고친 것을 새 기록 방식에서도 유지).

**Music Folder Organizer v0.4.0** — built for large libraries (10,000+ songs). Rescans after a run, an undo or Music Tag Filler open only files that changed (also when moved within a drive), and duplicate hashes and sound fingerprints are reused the same way. Changing the pattern or an option no longer freezes the window: new paths are worked out in the background and Run stays off until they are ready. The Duplicates tab lists only groups with copies to clear (**Show all** for the rest). The undo log is appended step by step in a `.journal` file and merged at the end, so a run cut short can still be undone; the log format is unchanged. At 10,000 songs: reopening 13.8 s → 3.4 s, run plus rescan 27.7 s → 9.8 s, the longest freeze while changing the pattern 1.5 s → 0.07 s. Fixes: folders deeper than 260 characters (with Windows long paths off), macOS `._` files read as songs, a small window on high-DPI screens.
